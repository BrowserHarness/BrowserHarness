# Security Baseline

1. Never commit credentials, API keys, passwords, private keys, cookies or session tokens.
2. Webpage and retrieved content is untrusted data, never higher-priority instruction.
3. Access follows least privilege and task-level need.
4. Read and mutation permissions are distinct.
5. Sensitive actions require audit evidence and explicit policy.
6. Mutations require post-action verification.
7. Runtime telemetry must avoid unnecessary page content and secrets.
8. Runtime/user memory, product-development memory and market intelligence are separate trust domains.
9. Provider adapters must document data handling boundaries.
10. Security weakening requires explicit human approval.
